# 레벨 곡선 시뮬레이션 (B-07)

> 이 문서는 `core/BloodRain.Sim` 이 만든다. 손으로 고치지 말고 데이터나 가정을 바꾼 뒤 다시 만든다.
> `dotnet run --project core/BloodRain.Sim -c Release -- --report docs/design/sim/level-curve.md`
> 진소운, 숭산 20분, 처음 열린 무공 8종, 연무장 없음. 정책마다 30판(시드 1~30), 조정 시험은 20판, 민감도는 10판의 중앙값.
> 적 구성과 사건은 아직 웹 프로토타입의 옛 1장 표(`Assumptions.EnemyMix`·`Events`)를 쓴다. 생성 곡선은 한 생 곡선(18분 뒤 400, 생성 중지 없음)이다. `chapters.json` 한 생 흐름과 축척·덩이는 T-17에서 얹는다.
> 돌리는 법과 모형 설명: [README.md](README.md). 가정 값의 원본: `core/BloodRain.Sim/Assumptions.cs`.

## 요약

- 지금 데이터(처치 진기는 프로토 값)로 평균 빌드의 레벨은 5·10·15·20분 Lv16·39·65·89. 목표(Lv15·30·45·60) 대비 +7% / +30% / +44% / +48%.
- 목표 ±25% 띠를 벗어나는 시점: 10분, 15분, 20분. 세 정책 모두 비슷하게 높다.
- 10~18분 동안 살아 있는 적은 생성 목표의 76~81%에 머물고, 그중 플레이어 곁에 닿아 맞을 수 있는 적은 31~42마리뿐이다. 생성 목표는 늘어나는데(180 → 400) 곁의 적은 늘지 않는다. 닿는 족족 잡는다는 뜻이고, 그러면 레벨 속도는 무공 세기보다 적이 다시 채워지는 속도(`spawnFractionPerSecond`)와 마리당 진기가 정한다.
- 그래서 적 기혈 증가를 0.08 → 0.2로 올려도 20분 레벨은 거의 그대로다(Lv89 → Lv86).
- 19분 화면 위 적은 중앙 309마리다(생성 목표 400). 생성은 매초 '목표 − 지금 수'의 30%만 채우므로, 초당 K마리를 잡으면 생성 직전 화면 적은 목표보다 약 K÷0.3마리 적은 데서 멈추고, 분당 표가 재는 생성 직후에는 K마리가 더해진다. 평균 빌드는 18~19분에 초당 38마리를 잡는다(400 − 38÷0.3 + 38 ≈ 310).
- 검산: 웹 프로토타입 자동 판 기록(`web/prototype/README.md`: 5분 Lv15 안팎, 원각까지 간 판은 20분 Lv75~100)과 지금 데이터 결과(5분 Lv16, 20분 Lv85~96)가 비슷하다. 화면을 그리지 않는 모형치고 크게 빗나가지 않는다.
- 처치 진기를 새로 정하고(P-02) 짝 심법 기준을 Lv3 → Lv2로 내리면 기획서 목표에 붙는다. 레벨 5·10·15·20분 Lv15·29·46·64, 절정 11.7분·초절정 16.0분, 첫 절기 15.4분·둘째 16.0분(아래 '조정 제안').

### 추천(작은 변경부터)

1. **처치 진기를 데이터로 옮기면서 낮춘다(P-02 결정과 같이).** enemies.json 에 `xp` 를 새로 두고 시강·혈인·혈강시·혈무사 1, 목인나한·동갑시 2(프로토는 1·1·2·3·3·4). 처치 진기는 아직 데이터에 없는 프로토 값이라(P-02) 지금 정하면 바꾸는 비용이 가장 적다. 이것만으로 레벨이 목표에 붙는다(5·10·15·20분 Lv15·29·46·64). 기존 숫자를 고치는 게 아니라 비어 있는 값을 채우는 일이라 다른 계산에 번지지 않는다. Core `EnemyDef` 에 `Xp` 를 더하고 웹 프로토타입 `spawnEnemy` 의 진기 표를 그 값으로 바꾸면 된다.
2. **짝 심법 기준을 Lv2로(1과 같이).** balance.json `evolution.pairPassiveMinLevel` 3 → 2. 1만 하면 첫 절기가 15.5분, 둘째는 14/20판에서만 깨어난다. 같이 하면 첫 절기 15.4분, 둘째 16.0분(19/20판). 기획서 8장의 '절정 무렵이나 15분 보갑 / 초절정 돌파'에 가깝다. 바꾸면 기획서 3장·8장의 'Lv3', balance.json·evolutions.json `_note`, `LoadoutTests` 의 '짝 심법 Lv2는 아직 문턱 아님' 검사도 같이 고친다.
3. **(1 대신) 프로토 진기를 그대로 둔다면 곡선 뒤쪽을 가파르게.** balance.json `xpCurve.segments` 둘째 step 13 → 30, 셋째 base 455 → 795, step 16 → 45. 레벨 21부터 필요한 진기를 늘려 공급이 많은 후반 레벨 속도만 늦춘다(초반 곡선은 그대로). 레벨은 1보다 조금 높고(5·10·15·20분 Lv16·34·51·66), 레벨 60까지 누적 진기가 바뀌어 기획서 11장의 '약 20,300'과 `BalanceTests` 도 고쳐야 한다. 그래서 1을 먼저 권한다.

### 고르지 않은 것

- `refill`(채움 비율 0.1): 레벨은 내려가지만(Lv14·32·52·72) 19분 화면 적이 189마리로 줄어 적이 화면을 메우는 맛이 사라진다.
- `health`(기혈 증가 0.2): 레벨이 거의 안 늦어진다(Lv16·36·61·86). 닿는 족족 잡는 상태라 적이 단단해져도 공급이 그대로다.
- `kill-xp+health`(진기 + 기혈 증가 0.3): 레벨은 목표보다 조금 낮아지고(Lv14·25·40·58) 19분 화면 적은 313마리. 19분 적 기혈이 지금의 2.7배인데도 화면은 별로 안 찬다.
- `refill+kill-xp`: 둘을 같이 낮추면 띠 안이긴 해도 네 시점 모두 목표보다 낮다(Lv13·24·38·52).

### 같이 볼 것

- 혈나한 원각(기혈 90,000): 추천안 20분 화력(단일 1,399)으로 잡으면 64초 걸린다(목표 60초). 60초에 맞추려면 기혈 약 84,000. 보스전에는 잡몹과 패턴 피하기가 끼므로 이 시간은 가장 짧게 잡은 값이다.
- 추천안에서도 20분까지 19,618마리를 잡는다(시드 1은 12분에 5,000). 음공 해금 조건 '한 판에서 적 5,000 처치'는 평균 판이면 저절로 열린다.
- 화면 적이 생성 목표 400에 못 미치는 건 위 요약대로 생성 규칙 때문이다. 기획서 11장의 '화면 위 적 400마리'를 '생성 목표'로 읽을지, 실제로 보이는 수로 읽을지 정해야 한다. 보이는 수를 400에 맞추려면 생성 목표나 채움 비율을 올려야 하는데, 둘 다 진기 공급을 늘리므로 처치 진기를 이 시뮬레이터로 다시 맞춘다.
